# 決算日推定の修正（遅れバイアス）

## 原因（事実）

1. **10-Q/10-K の提出日を混ぜていた** — `lastEarningsRelatedFilingDate` が 8-K 2.02 と四半期報告書のうち**遅い方**を採用。10-Q は決算発表 8-K より数週間後になり、起点が遅れる。
2. **+91「営業日」** — 旧 `estimateNextEarningsFromLast` は約 91 **取引日**（≈4.5か月）を加算。四半期は **91暦日**（≈3か月）が妥当で、系統的に遅い。
3. **Yahoo EPS の `nextEarningsDate` をそのまま採用** — ORCL/NKE などで 2027 年台の遅い日付が入り、EDGAR 補正前に `resolve` が Yahoo を優先していた。
4. **表示レンジの不具合（修正済）** — 過去の YoY/逐次候補をウィンドウに混ぜ、`推定 11/3〜8/3` のように終端が始端より前に見えていた。**今日以降のみ**を `earliest`/`latest` にする。
5. **確定日の上書き（修正済）** — `enrichEarningsDate` が **Yahoo を Nasdaq カレンダー（確定）より先**に見ていたため、AKAM/VST/VRT なども `推定 M/D〜M/D` になっていた。**Nasdaq カレンダー確定を最優先**し、確定時は `estimateLabel` を付けない（通常の5営業日警告のみ）。
6. **2.02 の密集（修正済）** — 60日以内の複数 2.02（修正8-K・二重提出）を四半期として数え、ベンチが「次四半期」誤認していた（下記）。

## 新アルゴリズム

- 起点は **8-K Item 2.02 の filing date のみ**。一覧は **60暦日未満の後続 2.02 を除外**（`thinItem202ToQuarterlyCadence`）。
- 次回候補: **前年同四半期**（+364暦日）と **+91暦日**。`today` 以降に繰り上げ、**早い方**を点推定。
- **確定**（Nasdaq カレンダー / watchlist `status: confirmed`）があるときは EDGAR/Yahoo マージ・`estimateLabel` は使わない。
- **推定**のみ: Yahoo/Nasdaq summary と EDGAR を **min** マージ、`estimateLabel` と 10営業日警告（`estimateEarliest`）。

## 解釈

遅い推定は「決算まで余裕あり」と誤判定し、**新規回避ルールを弱める**方向のバイアス。確定日はそのまま保守的な5営業日ルール、推定のみ EDGAR 補正と広めの10営業日警告。
