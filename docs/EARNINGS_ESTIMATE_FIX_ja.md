# 決算日推定の修正（遅れバイアス）

## 原因（事実）

1. **10-Q/10-K の提出日を混ぜていた** — `lastEarningsRelatedFilingDate` が 8-K 2.02 と四半期報告書のうち**遅い方**を採用。10-Q は決算発表 8-K より数週間後になり、起点が遅れる。
2. **+91「営業日」** — 旧 `estimateNextEarningsFromLast` は約 91 **取引日**（≈4.5か月）を加算。四半期は **91暦日**（≈3か月）が妥当で、系統的に遅い。
3. **Yahoo EPS の `nextEarningsDate` をそのまま採用** — ORCL/NKE などで 2027 年台の遅い日付が入り、EDGAR 補正前に `resolve` が Yahoo を優先していた。
4. **表示レンジの不具合（修正済）** — YoY/逐次候補のうち**過去日**をウィンドウに混ぜ、`推定 11/3〜8/3` のように終端が始端より前に見えるラベルになっていた。**今日以降のみ**を `earliest`/`latest` にし、同年は `M/D〜M/D` の昇順で表示。

## 新アルゴリズム

- 起点は **8-K Item 2.02 の filing date のみ**（提出日リスト）。
- 次回候補: **前年同四半期**（直近 2.02 + **364暦日**）と **直近 +91暦日**。`today` 以降に繰り上げたうえで **早い方**を点推定。
- 表示: `推定 M/D前後` または `推定 M/D〜M/D`（`estimateLabel`）。レンジは点推定 ±7暦日、YoY/逐次が21日以内なら両候補を挟む。
- Yahoo/Nasdaq 推定日は EDGAR 2.02 推定と **min（早い方）** でマージ（レンジも min でクリップし `earliest <= latest` を保証）。
- 警告: 推定は **`estimateEarliest` から10営業日以内**でも赤（既存の点日付ベース警告も維持）。
- `resolveEarningsInput` は **enrich キャッシュを Yahoo より先**に参照。

## 8四半期ローリングベンチマーク（実 EDGAR 2.02）

実行例（メールはコミットしない）:


## 解釈
