# レンジ表

米国株ウォッチリストの終値が、直近20日の高値と安値（箱）のどこにあるかを、電話で一目見て確認するための表。読み取り専用で、証券口座には接続しない。注文も出さない。

箱の位置は `(終値 − 20日安値) ÷ (20日高値 − 20日安値)`。0%が底、100%が天井。底の近くが買い場、天井の近くが全売りの目安、という見方用。

## ローカルで動かす

```bash
npm install
npm test
npm run dev
```

ブラウザで [http://127.0.0.1:43123](http://127.0.0.1:43123) を開く。初回は全銘柄の日足を取るので数十秒かかることがある。2回目以降は15分間キャッシュを使う。

APIキーは不要。価格はサーバが [Yahoo Finance の日足チャート](https://query1.finance.yahoo.com/v8/finance/chart/) を取得して計算する。

## 銘柄の追加と削除

`data/watchlist.yaml` を編集する。価格は書かない。

```yaml
- ticker: NVDA
  description: AI向けGPUの本命。AI設備投資の中心
  notes: 連動中/MU低
  # watchOnly: true          # 監視のみ
  # tags: [高ボラ]
  # earnings:
  #   date: 2026-10-15       # YYYY-MM-DD
  #   status: confirmed      # confirmed（確）または estimated（推定）
```

保存してページを更新すると、新しいティッカーだけ取りにいく。すでにキャッシュにある銘柄の再計算は15分に1回まで。決算日は季節ごとに手で更新する。

## 保有（非公開）

リポジトリは公開なので、保有・株数・取得単価・残高・口座番号・明細CSVはコミットしない。保有は Render の Secret 環境変数 `HOLDINGS_JSON` に置く（Dashboard → サービス → Environment）。未設定でもサイトは動き、保有との相関が「—」になる。ONDS は書いても無視する。

```json
{
  "holdings": [
    { "ticker": "AAA", "shares": 3, "avgCost": 101.5, "reviewLine": 95 }
  ],
  "cash": { "usdSettled": 250, "usdUnsettled": [{ "amountUsd": 120, "settleDate": "2026-10-05" }], "jpy": 10000 },
  "defenseLineJpy": 123456
}
```

`ticker` と `shares` 以外は省略できる。`npm test` のプライバシーテストは、`U` + 7〜8桁の口座番号、CSV などの明細ファイル、`data/` 内の株数を見つけると失敗する。

## アラート `/api/alerts`

外部のアシスタントがポーリングして通知に使う JSON。サイトは通知を送らない。画面は `/alerts`。

- 項目ごとの `id` は市場データや提出番号だけから決まる。再起動しても同じ出来事は同じ `id` なので、アシスタントは `id` で重複を除けばよい。
- `eventAt`（UTC）と `eventAtJst`。入口シグナルはその日の引け（16:00 ET）、EDGAR は受付時刻。
- `priority` は `critical` / `high` / `normal` / `low`。`?since=<ISO>` で `eventAt` 以降だけに絞れる。
- `complete: false` のときは EDGAR の巡回が途中。1分ほどあとにもう一度読む。

| kind | 条件 |
|---|---|
| `entry_in_ok` | IN OK・ATR14が終値の3%以上・決算5営業日以内なし。監視のみと ONDS は除く。決算日未登録は `low` と `no_earnings_date`。id は `entry:{T}:{IN OKが続いている初日}` |
| `sec_8k` | 8-K / 8-K/A。Item 1.01・1.02・1.03・1.05・2.01・3.01・4.02・5.01 は `high`、それ以外は `normal`。2.02（決算）・7.01・9.01・5.07 だけの提出は出さない |
| `sec_form4_sell` | Form 4 の市場売却（コード S）が合計 $250K 以上で、10b5-1 計画のチェックも脚注も無いもの。$5M 以上は `high` |
| `sec_offering` | 424B1/B3/B4/B5/B7。424B2（仕組債）と金融グループは出さない。株か社債かはリンク先で確認 |
| `anthropic_s1` | 提出者名が Anthropic 本体と完全一致する S-1/S-1/A/F-1/424B4。`critical`。直近30日 |

SEC の3種は watchlist の銘柄（ONDS を除く）の受付から4日以内。id は `sec:{提出番号}`。CIK は `data/sec_cik.json`（公開情報）で、ウォッチリストを変えたら `SEC_USER_AGENT=... npx tsx scripts/build-sec-cik.ts` で作り直す。1社ずつ順に読み、各社30分キャッシュ。起動直後の1巡は約80秒かかり、その間は `complete: false`。

EDGAR は Render の環境変数 `SEC_USER_AGENT`（例 `range-table you@example.com`）が無いと止まる。SEC は連絡先メールの無い User-Agent に 403 を返すため。メールはリポジトリに書かない。

## 取引ログ `/log`

IBKR の CSV（アクティビティ・ステートメントの日本語版・英語版、または取引履歴）を選ぶと、ブラウザの中だけで読んで約定を取り出す。サーバには送らず、保存先はその端末の localStorage（`rt.fills.v1`）。口座番号や CSV そのものは保存しない。

- 損益は手数料込みの FIFO。買い手数料は1株あたりに按分し、売り手数料は売却額から引く。同じ銘柄の同じ日の売りを1トレードと数える。
- 「$10達成日」は、決済があった米国の取引日のうち、その日の確定損益の合計が $10 以上だった日数。
- 期間より前に買った株の売りは、IBKR の実現損益があればそれを使い、無ければ集計から外して警告を出す。
- FX の表・配当・入出金・オプションは読み飛ばす。ONDS は取り込まない。
- 同じファイルを何度選んでも重複しない。アクティビティと取引履歴で同じ日を両方取り込んだ場合は、先に入っていた方を残す。
- 機種変更の前に「JSONで保存」。テストの fixture はすべて架空（`src/lib/fixtures/*.synthetic.csv`）。

## チーム注目

`data/team_picks.json` は配列。空のときは「チームの推奨は朝に更新されます」と出る。中身を足すと `/picks` のカードと `/api/picks` に載る。ウォッチリストに無いティッカーだけ、同じ同時数で日足を取る。

```json
{
  "ticker": "VRT",
  "name": "Vertiv",
  "genre": "電力",
  "thesis_facts": "事実",
  "thesis_hypothesis": "仮説",
  "entry_line": 100,
  "entry_basis": "根拠",
  "review_line": 150,
  "review_basis": "根拠",
  "earnings_date": null,
  "status": "候補",
  "recommended_by": "名前",
  "as_of": "2026-10-01"
}
```

`status` は「候補」か「監視のみ」。終値がエントリーライン以下なら「エントリー圏」。終値が450ドルを超えるか、ステータスが監視のみなら「監視のみ」。決算日が5営業日以内なら「決算5営業日以内」。距離は `(終値 − ライン) ÷ ライン`。

## 数字の根拠

| 表示 | 計算 |
|---|---|
| 終値 | 確定した日足の終値。場中の未確定の足は入れない |
| 20日線 | 直近20本の終値の単純平均 |
| 20日線の傾き | 今日の20日線 ÷ 5営業日前の20日線 − 1。±1%未満は横ばい、それ以上は上向き、それ以下は下向き |
| 乖離 | (終値 − 20日線) ÷ 20日線 |
| 20日安値 / 20日高値 | 直近20本の安値の最小、高値の最大 |
| 箱の位置 | (終値 − 20日安値) ÷ (20日高値 − 20日安値) |
| ATR(14) | 直近14本の真の値幅（TR）の平均 |
| 上抜け | 終値が、当日を含まない直前20本の高値より上 |
| 箱の天井付近 / 上抜け継続 | 箱の位置が80%以上。上抜けも付いているときは「上抜け継続？（売り急ぎ注意）」。買いサインではない |
| 決算までの営業日 | 米国東部の今日を含めず、翌営業日から決算日までのNYSE営業日。5以内で警告 |
| 実績PER / 予想PER | 確定終値 ÷ Yahoo Finance の過去12か月EPS、または予想EPS。EPSは約24時間キャッシュし、株価は日足キャッシュのまま。EPSがマイナスなら「赤字」。取れなくても箱の数字は出す |
| 利益回復中 | 実績PERが予想PERの2倍以上 |
| 出来高 | Yahoo日足。倍率=直近日の出来高÷直前20日平均。薄商いは0.7倍未満、急増は1.5倍以上。上抜け継続で倍率が1倍未満のときは「出来高伴わず」。売買代金は終値×出来高の20日平均 |
| 相関 | 60営業日の日次リターン相関。保有は Render の Secret 環境変数 `HOLDINGS_JSON` の株数×最新終値で加重（ONDS は除外）。未設定なら「—」。もう一方は SOXX。窓とベンチマークは `data/corr_basket.json`。カードは小数2桁。0.3以下は「低相関」 |
| チーム注目の距離 | (終値 − エントリーまたは見直しライン) ÷ ライン |

画面上のフィルタ「箱の底 ≤20%」「箱の天井 ≥80%」はこの百分率。SPY・QQQ・SOXX は同じ20日線からの乖離。価格は米ドル。分割がある場合は分割調整し、配当調整はしない。

## Render に置く

`render.yaml` がある。リポジトリを GitHub に置いたあと:

1. [Render Dashboard](https://dashboard.render.com/) → **New** → **Blueprint**。
2. このリポジトリを選ぶ。`render.yaml` の Web Service が読まれる。
3. 設定はそのままで作る。ビルドは `npm ci && npm run build`、起動は `npm start`。
4. 起動コマンドは `0.0.0.0:$PORT` にバインドする。`PORT` は Render が渡す。
5. ヘルスチェックは `/api/health`。日足の取得には依存しない。
6. デプロイが終わったら `https://<サービス名>.onrender.com` を電話で開く。

Blueprint を使わない場合は **New → Web Service** で同じビルドコマンド、起動コマンド、ヘルスチェック、Node 22 を指定する。

無料枠のインスタンスはしばらくアクセスがないとスリープする。起きた直後の1回目は、キャッシュが空なので日足の取得が終わるまで待つ。取得結果はインスタンス上の `data/.cache/` に15分保存する。このディレクトリはデプロイのたびに消えてよい。
